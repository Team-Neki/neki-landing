# 브라우저 검수

UI 변경 시 관련 시나리오를 실행한다. 공통 CSS·스크롤·상태 변경은 전체 흐름을 확인한다. 아래 항목은 수동 검사이며 자동화되었다고 보고하지 않는다.

| 환경 | 확인 |
|---|---|
| 모바일 390×844, 375×667 | 가로 넘침, 첫 화면 버튼, 하단 고정 CTA 겹침 |
| 중간 폭 768×1024 | 섹션 전환, 폰 크기, 버튼 접근 |
| 데스크톱 1440×900, 1366×768 | 고정 구간, 제목·버튼 잘림, QR |
| 동작 줄이기 켬 | 본문·사진·조작이 남아 있고 과한 모션이 생략되는지 |
| 키보드 | Tab 포커스, 셔터·포즈·FAQ 조작 |

## 핵심 흐름

1. 셔터를 누르고 네 칸이 채워지는지 확인한다. 촬영 중 다시 눌러 재시작한다. 아카이빙·다운로드에 같은 네컷이 반영되는지 확인한다.
2. 공감 대화와 해결 카드가 연결되고 기능 링크가 해당 영역으로 이동하는지 확인한다.
3. 지도에 진입해 검색→결과→매장 선택→길찾기가 이어지는지 확인한다. 위로 되돌아갔다 재진입한다. 모바일 시간 전환도 확인한다.
4. 포즈 1·2·3·4명을 차례로 선택한다. 2명에서만 관계 선택이 보이는지 확인한다. 랜덤 추천과 빠른 연속 선택 후 화면 상태를 확인한다.
5. 아카이빙을 끝까지 스크롤하고 반대로 올라온다. 내 네컷과 앨범 장수, 카드 위치, 고정 구간 종료를 확인한다.
6. FAQ를 바꾸어 열고 한 항목만 열리는지 확인한다.
7. 모바일 다운로드의 OS별 이동, 데스크톱 QR과 app.html의 스토어 연결을 확인한다. 휴대폰에서 접근 가능한 URL로 QR을 검사한다.
8. 이미지 로드 실패·콘솔 오류·가로 넘침을 확인한다. 3D 실패 시에도 본문과 다운로드를 사용할 수 있어야 한다.

검수 결과에 날짜, 브라우저/기기, 화면 크기, 성공·실패·미실행과 증거를 남긴다. 실기기 터치와 에뮬레이션 결과는 구분한다.
